## Containerised hosted profile and an in-process stall watchdog

Deployment question: run coxswain-hosted under Docker, no Podman. The binary
itself containerises without trouble (pure Rust, vendored protoc). What does not
carry over is the systemd `WatchdogSec` path: Docker restarts only a process that
exited, and a `Type=notify` unit wrapping `docker run` cannot receive notify
messages, because the container sits in dockerd's cgroup, not the unit's.

So the wedged-but-alive case moves into the process: `stall_watchdog.rs`, a
thread that aborts when the loop stops beating for 1 s. It works under any
supervisor that restarts on exit, and with none the process still dies rather
than holding stale outputs. Kept the sd_notify ping; under systemd both run and
ours fires first.

Did not reuse `conn_node.watchdog_ms`. That field is the hardware watchdog's kick
interval, a different quantity, and 250 ms would trip on ordinary Linux jitter.
A false abort costs a restart. The hardware watchdog (Phase 8) is still the
backstop for a process too stuck to schedule this thread.

Surprise during the smoke test: as container PID 1 the binary ignores an external
SIGABRT, because the kernel drops unhandled signals to init. abort() from inside
still terminates, but only through glibc's fallback (exit 139, SIGSEGV), not
SIGABRT (134). `init: true` in compose restores ordinary semantics and also stops
`docker stop` from waiting out its timeout. Verified: abort inside the container
under `--init --restart always` gives RestartCount 1 and a running loop.

Restart backoff is Docker's: doubling from 100 ms, reset after 10 s up. During a
restart the actuator-side heartbeat failsafe (D-010, D-027) holds, same as under
systemd.

## SIL backend proposed (D-034)

Started from "Keelson as a sensor interface and output backend". On a real
vessel that is invariant 1 whether opt-in or not. Reframed as a test-only I/O
backend it is fine: the exclusion with `--port` is what makes it safe, not
Docker, since the production image is Docker too. Chose free-running clocks over
lockstep, so a SIL run sees jitter and loss like hardware; reproducibility stays
with `--sim` and replay. Own keyspace, because reusing `location_fix` would make
Coxswain ingest its own telemetry. Drafted as proposed, not yet accepted.
