# 2026-11-26

## D-035 rewritten after keelson #399

Keelson #399 proposes `conn/v1`, adopted from Coxswain's conn protocol. The
first reading was to co-own it. Rejected: a jointly owned wire format ties
Coxswain's pace to Keelson's, and Coxswain has to run with Keelson absent
anyway. D-035 now says Coxswain owns the conn's meaning (the supervisor's rules
and the contract types) and the Keelson adapter implements whatever standard
interfaces Keelson settles on, translating. Share vocabulary, own contracts.

A first draft refused `vehicle_navigation/v1` and `vehicle_lifecycle/v1`
arm/disarm as "needing the adapter to act as a claimant". Wrong on the facts:
`Setpoint` already has `StationKeep` and `FollowPath`, the supervisor already
has holder-only `arm`/`disarm`, and liveness is the claimant's heartbeat, not a
setpoint stream. So both are served as the calling station's own claimant
operations. What stays forbidden is the adapter keeping anything alive on a
station's behalf.

Open: whether a station's Keelson liveliness token may count as its heartbeat.
Leaning no (it survives a hung application); settle with Keelson's conn
interface. The `safety_state` stop concern was kept out of the #399 comment
until the stop-sources decision is made.

## Guidance references as Keelson setpoints (D-036 proposed)

Keelson #316 has the executor publish `<measurement>_setpoint`. For the
vessel that is guidance, which until now kept its references as locals. Two
findings shaped the subject choice: the yaw loop closes on heading in every
mode, LOS included (course commanded as heading, crab unmodelled), and the
speed loop closes on body surge over ground, with no STW or current estimate
anywhere. So heading goes on `heading_true_north_deg_setpoint` and speed on
`speed_over_ground_knots_setpoint`, the nearest honest subject, with the crab
limit stated in the entry. Changing the loop to close on SOG for telemetry's
sake was rejected; whether it is better for control reasons is left open.

## Stops as a supervisor input (D-037)

Reading keelson #399 item 3 against `apply_rc_events` confirmed the defect:
the RC kill called holder-only `disarm` and ignored the error, so with
teleop or autonomy holding the conn the kill switch did nothing. The fix is
not a privileged disarm but a new kind of input. A stop is accepted from any
declared source because it only removes actuation; it disarms whoever holds
the conn, refuses arming, and leaves the conn alone. That is Keelson's
`safety_state` semantics too, so the same input takes it once #332 merges.

Choices made while implementing:

- Silence is judged in the supervisor from per-frame reports, with
  `claimant_heartbeat` as the window. A never-heard source counts as silent.
  An engaged stop holds through silence.
- The RC adapter now reports kill as a level every frame, not as edges, and
  zeroes effort under a kill instead of withholding it. Withholding cost the
  RC claimant its heartbeat, and so its conn, during a stop.
- `[rc.claimant]` became a sub-table rather than a set of optional fields,
  following D-030's nesting rule.
- `--sim` drops the RC stop source: no link is opened, and judging its
  silence would read as a dead transmitter.

The desk rig now kills while teleop holds the conn. Emptying
`Core::stop_report` makes it time out waiting for the stop, which is the
regression the rig exists to catch.

## Unregister, conn events, base path (D-038)

Eviction of silent claimants was the first proposal for freeing registry
slots. Rejected in review: with every claimant alive it frees nothing, and it
punishes a claimant that is quiet by design. An explicit `unregister` is the
only way a slot frees now; Keelson's interface has none, so the adapter will
infer one from the station's liveliness token, or a long silence, when that
interface is served.

The base path first looked like a hosted flag. It is not: the H7 has no
command line, and a compile-time constant means a firmware image per fleet.
It is the other half of the key prefix `vessel_id` already starts, so it went
into the manifest beside it. The integration harness now runs under
`cox_it/fleet`, so every one of its tests checks the field reaches the keys.

Conn events are derived in the hosted loop by comparing the supervisor's conn,
arming and failsafe around each call and tick, which keeps the supervisor
untouched. The end-to-end test sees armed, unregistered, then the
claimant-lost failsafe that a release while armed latches, in that order.

## Turn order (D-039)

The first lead bound was the heading error at which the yaw demand
saturates. On the example vessel that is 150 / 43.75 = 3.4 rad, past half a
turn, so it bounds nothing that matters: the reference can still flip behind
the heading. The bound is now that or a quarter turn, whichever is smaller.

A mutation check found the first version of the test blind to the flip. The
damping term acts on the yaw rate's error from the ordered rate, so
`kd * rate` keeps the demand pointing the ordered way for a while after the
reference has flipped. The test now asserts the reference stays on the
ordered side of the heading, and catches the unbounded lead at t = 3.2 s.

Closed loop on the example plant: 3.00 deg/s achieved for 3.00 ordered.
